# AGENTS.md

Repository-specific guidance for AI agents working on EconovaFX.

## Git identity

```

```

Set it before committing:

```bash
git config user.name "yasmramos"
git config user.email "yasmramos95@gmail.com"
```

## Commit messages

- Follow [Conventional Commits](https://www.conventionalcommits.org/), in English
  (see `CONTRIBUTING.md` for the full policy). The `.githooks/commit-msg` hook
  rejects messages that do not match `<type>[optional scope]: <description>`.
- Use the imperative mood, lowercase description, no trailing period.

## No AI attribution

Commit messages must contain **no** AI attribution and **no** `Co-authored-by:`
trailers. Never add a co-author line, "generated by", or any AI/tool credit.

## Push

- Feature work and PRs target `develop` (`CONTRIBUTING.md`).
- Do not push unless explicitly asked.

## Build and test

- Toolchain: JDK 17 target, builds on JDK 21. Run `mvn clean verify`.
- GUI/visual tests (TestFX + Monocle, headless) are excluded from the default
  run; execute them with `mvn test -Pvisual-tests`.

## Design system (desktop JavaFX UI)

The desktop UI follows the shadcn look. Do not touch `web-ui/` (Svelte) when
styling the JavaFX app.

- Colours live only in `src/main/resources/css/theme-tokens.css` as looked-up
  tokens (`-card`, `-border`, `-muted`, `-zinc-*`, ...). Never hard-code a hex
  value in another stylesheet or in FXML. `StyleTokenDisciplineTest` fails the
  build if a raw hex/`rgba()` shows up in any JavaFX sheet. The only exceptions
  are `theme-tokens.css` itself and `templates/reports/*` (plain HTML/CSS for
  the WebView and OpenHTMLToPDF, a different rendering engine).
- Style sheets are composed in this order: `theme-tokens` -> `controls` -> the
  screen's own sheets (`main-styles`, `sidebar`, `dashboard`, `dialog`,
  `login`...) -> `utilities` (utilities last so a Tailwind-style class always
  wins). Apply them through `StyleSheets`, never by hand.
- Token families:
  - structure: `-page` (page canvas), `-card`, `-popover`, `-border`, `-muted`.
  - text ramp: `-foreground`, `-muted-foreground`, `-fg-strong` / `-fg-body` /
    `-fg-subtle` / `-fg-faint` (behind the legacy `text-gray-*` / `text-slate-*`
    utilities). `bg-white` maps to `-card`, not to the page.
  - scroll bars: `-thumb` / `-thumb-hover`.
  - brand: `-brand` / `-brand-alt` (gradient), `-brand-hover`, `-brand-pressed`,
    `-brand-ring`, `-brand-tint`, and the `-brand-fg*` / `-brand-*-wash` /
    `-brand-track` foregrounds. Used only by the splash/login screens, the
    brand badges and the auth primary action.
  - data series: `-series-1..5` and `-series-1-wash` (chart palette; fixed in
    both themes because the hue carries meaning).
  - loading veils: `-page-veil` / `-card-veil`.
- The raw `-zinc-*` scale does **not** flip with the theme. Structural chrome
  must use semantic tokens that do (`-page`, `-thumb`, `-fg-*`, `-card`).
- Dark mode redefines the same tokens under `.root.dark`. `ThemeManager`
  toggles that class on the scene root and persists the choice with
  `java.util.prefs.Preferences` (never `ConfigFileUtil.saveProperties`, which
  rewrites the file and would drop database config).
- Modena leaks on some controls; reset them explicitly. The chart frame/plot
  area and the progress indicator both needed this (see `dashboard.css`,
  `controls.css`).
- A rounded surface with a visible border must declare `-fx-border-radius` equal
  to its `-fx-background-radius`, or JavaFX paints a square hairline that pokes
  out of the rounded corners (the "corner tip"). `StyleShapeDisciplineTest`
  fails the build otherwise. A rule that paints one hairline edge on purpose
  (a table header's bottom rule) is exempt because its border is not uniform.
- Table radii are 8, so the header's top corners are `8 8 0 0` (and the corner
  cell `8 0 0 0`); they used to say 7 and left a 1px ledge.
- Accessibility, enforced by `ContrastDisciplineTest` (default suite): it reads
  the tokens from `theme-tokens.css` and checks WCAG ratios in both themes.
  - Text pairs must clear 4.5:1, including a status hue used as text on a card
    *and* on its own `-*-soft` chip. That is why `-success` is green-700, not
    green-600: the lighter base was only 3.15:1 as 11px badge text.
  - The focus ring `-ring` must clear 3:1 (WCAG 1.4.11) on `-card`, `-page` and
    `-muted`. It is the one indicator a keyboard user has.
  - A status hue that is also a solid fill (`.btn-success`, ...) gets a matching
    `-*-foreground` token rather than literal `white`, so the ink flips in dark
    mode (dark ink on the lighter dark-mode fill).
- `.button:focused` sets `-fx-background-color: -ring-wash` for the outline
  variants. It carries a pseudo-class, so it outranks a plain variant class and
  would turn a focused solid button into a ghost; each solid variant re-states
  its fill under `:focused` to keep it. The ring border stays, and it reads
  against the page even where the fill is near-white.
- `.check-box`, `.radio-button` and `.toggle-button` focus with an outer
  `-fx-effect` glow rather than a border ring: their selected fill is `-primary`
  (near-white in dark), where a border ring would disappear against it.
- Regression tests for tokens/controls live in `ChartsAndThemeTest` and
  `StyleTokenDisciplineTest` (the latter runs in the default suite; the former
  with `-Pvisual-tests`). `StyleShapeDisciplineTest` and
  `ContrastDisciplineTest` run in the default suite.
